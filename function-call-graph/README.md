# Function Call Graph

Плагин IntelliJ IDEA для интерактивной диаграммы вызовов Kotlin/JVM и Java.
Версия **0.1.2** предназначена для **IDEA 2026.3 (263.*)** и JDK 25.
В IDEA должны быть включены встроенные плагины Java и Kotlin.

## Использование

1. Откройте Java- или Kotlin-файл и поставьте курсор на функцию/метод либо на её вызов.
2. Выберите **Show Function Call Graph** в контекстном меню редактора, меню **Tools** или через **Find Action**.
3. В нижней панели **Function Call Graph** появится диаграмма: вызывающие функции слева, выбранная в центре, вызываемые справа.
4. Щёлкните узел, чтобы увидеть входящие и исходящие места вызова. Двойной щелчок по строке списка (или Enter) открывает точное место в исходнике.
5. Двойной щелчок по узлу открывает его объявление. **Focus selected** строит диаграмму вокруг выбранного узла; **Refresh** пересчитывает её после изменений кода.

**Depth** задаёт глубину от 1 до 5 отдельно в каждом направлении. Стрелка всегда направлена от вызывающего к вызываемому. Цифра на ребре — количество мест. Рёбра, содержащие только ссылки на функции (`Class::method`, `::function`), показаны пунктиром; рёбра с непосредственными вызовами — сплошной линией. Тип каждого места также указан в списке.

Кнопки **+ / − / 100%** и Ctrl+колесо меняют масштаб. Диаграмму можно прокручивать; стрелки влево/вправо переключают узлы, Enter открывает объявление. **Cancel** останавливает расчёт.

## Что анализируется

- Явные статически разрешимые вызовы методов/функций и конструкторов, ссылки на функции.
- Отдельные перегрузки, повторные вызовы и циклы, включая рекурсию.
- Локальные Kotlin-ссылки `::function`, вызовы из `init` неявных конструкторов и выражений параметров по умолчанию. Последние показываются как возможные вызовы функции: при переданном аргументе значение по умолчанию не вычисляется.
- Входящие места использования в исходниках проекта, включая тестовые исходники.
- Вызовы внутри лямбд и инициализаторов получают собственный узел контекста. Объявление вложенной функции или создание лямбды не означает выполнения её тела: такие тела не приписываются внешней функции.
- Библиотечные методы отображаются как конечные узлы; их реализация рекурсивно не обходится.
- Расчёт выполняется в отменяемом фоновом read action после индексации и фиксации документов. Узлы хранят smart pointers для переходов после редактирования.

Это статическая диаграмма, а не трасса выполнения. Виртуальный вызов связан с объявлением, которое разрешила IDEA; все возможные реализации не подставляются. Reflection, DI, динамические вызовы, неявные Kotlin-операторы/аксессоры/делегаты и фактическое выполнение переданных callback не моделируются. Неразрешённые явные исходящие вызовы учитываются в счётчике на панели. Вызовы из внешних бинарных зависимостей не ищутся.

На диаграмме не более 120 узлов и 1500 мест вызова. При отсечении результата панель показывает **LIMIT REACHED**; уменьшите глубину или выберите другой центр. Диаграмма является снимком — после правок используйте **Refresh**.

## Сборка и установка

Плагин — модуль общей Gradle-сборки. Настройте `JAVA_HOME` на JDK 25 и выполните из корня:

```bash
./gradlew :function-call-graph:check :function-call-graph:buildPlugin
./gradlew :function-call-graph:runIde -PlocalIdePath=/path/to/intellij-idea
```

Общий параметр `localIdePath` выбирает установленную IDEA; без него Gradle загружает SDK.
ZIP находится в `function-call-graph/build/distributions/function-call-graph-0.1.2.zip`.
Скрипт `./build-plugins.sh` собирает все три плагина в `local.dists/`.
Общая конфигурация и проверки описаны в [корневом README](../README.md).

Для установки откройте **Settings → Plugins → ⚙ → Install Plugin from Disk…**, выберите ZIP
и перезапустите IDEA, если она предложит это сделать.

## Проверки

Тесты в `src/test/java` используют IntelliJ light fixtures с настоящими PSI/UAST. Они проверяют
разрешение вызовов Java/Kotlin, перегрузки, ссылки на функции, глубину обхода, рекурсию,
контексты лямбд/инициализаторов и ограничения размера. Отдельные тесты проверяют отрисовку,
клавиатурную навигацию и масштаб. Задача `check` также запускает Plugin Verifier на общем SDK.

Для ручной проверки после установки откройте `examples/Demo.java` и `examples/Demo.kt`
из этой папки в Java/Kotlin-проекте, вызовите действие на `process` и проверьте переходы
по узлам и местам вызова.

API анализа: [UAST в IntelliJ Platform SDK](https://plugins.jetbrains.com/docs/intellij/uast.html).
